# 地区人数 · 隐私预算统计原型

对项目内**固定的一份人员样本**开放“单地区人数”查询：先按明确规则为每人保留一条有效地区记录，
再用拉普拉斯机制返回加噪人数，并按 ε 预算做扣费、重放与失败回滚。

> 这是一个覆盖范围很窄的原型，不是通用隐私保障系统。适用边界见页面“机制与边界”页与
> `app/contract.js` 中的 `boundaries`。

## 运行

需要 Node.js ≥ 22.5（使用内置 `node:sqlite`，无第三方依赖）。

```bash
npm start          # http://127.0.0.1:8787
npm test           # 35 个测试：流水线、归一化、拉普拉斯、事务/并发/持久化、锁定流程
npm run generate:sample   # 打印确定性样本的生成统计（不写文件）
```

环境变量：

| 变量 | 默认值 | 说明 |
| --- | --- | --- |
| `PORT` / `HOST` | `8787` / `127.0.0.1` | 监听地址 |
| `PRIVACY_DB_PATH` | `var/privacy.sqlite3` | SQLite 单文件状态 |
| `PRIVACY_ADMIN_TOKEN` | `demo-admin-token` | 演示用管理员令牌 |

## 首次使用顺序

1. 打开页面 → “数据处理”标签 → 输入管理员令牌 → **确认并锁定**。
   锁定写入样本、贡献规则、查询契约三组哈希；之后改名/替换数据会在启动时被检测为冲突，
   查询会被拒绝，已有预算与流水不受影响。
2. “预算与流水”标签 → 设置总 ε（只可设置一次；产生成功查询后封存）。
3. “查询”标签 → 勾选地区、填写每地区 ε → 提交。费用 = 地区数 × ε。

重启程序后锁定、预算、流水、历史与重放状态都从 SQLite 恢复。

## 数据准备规则（`app/pipeline.js`）

1. 只接受 6 位地区代码，且必须能在固定地区表中找到；空值、空字符串、未知代码的行剔除。
2. 同一人、同一来源、同一地区的重复行合并，保留更新时间最新的一条。
3. 有效候选按来源优先级排序：居住申报(4) > 户籍登记(3) > 手机归属地(2) > 登录日志(1)；
   同优先级取更新时间较新的。
4. 每人只保留排序后的第一条；被替换的记录按“按优先级替换”计数，不删除原始行。
5. 没有任何有效记录的人整体剔除，不产生地区贡献。

页面“数据处理”标签展示逐阶段人数、来源优先级、以及覆盖冲突/重复/无效/整人剔除/普通情况的
代表样本，并标出每条原始记录的去向。

## 隐私与记账设计

- **敏感度**：严格一人一条记录 ⇒ 单地区计数敏感度 Δ = 1；噪声尺度 ns = 1/ε。
- **组合**：一次提交中每个地区是独立查询，按基本组合定理分别消耗 ε，总费用 = 地区数 × ε。
- **查询身份**：`SHA-256(样本哈希, 契约哈希, 敏感度, 排序后的地区代码, 以 1e-6 为单位的 ε)`。
  地区名称、勾选顺序、界面标签、请求编号都不参与。相同身份命中成功记录 → 直接返回保存结果，
  `deduplicated` 计数递增，不再抽样、不再扣费。
- **预算记账**：整数 micro-ε（1e-6）避免浮点漂移；扣减在 `BEGIN IMMEDIATE` 事务内用条件
  `UPDATE ... WHERE spent + ? <= total` 完成，并发提交不会把余额扣成负数。
- **失败路径**：预算未设置、预算不足、请求非法只写 `attempts` 审计行，不写 `queries`/`ledger`，
  不扣费；执行中抛错则整个事务回滚。
- **两种结果值**：`raw_noisy`（机制直接输出，可负）与 `display_value = max(0, raw_noisy)`
  分开写入、同时返回。非负截断是展示变换，会改变分布（期望约偏高 ns/2），不是“更好的噪声”。
- **真值隔离**：查询响应不含真值；真值只来自独立的 `GET /api/truth` 与“真值对照”标签页，
  用于理解误差，不参与预算与流水。

## 目录

```
app/
  pipeline.js     去重/剔除/优先级 → 每人一条记录
  laplace.js      安全随机源、拉普拉斯抽样、非负展示值
  normalize.js    地区/ε 归一化与查询指纹
  store.js        SQLite 事务：锁定、预算、查询、流水、失败审计
  service.js      查询编排（扣费成功后才抽样）
  instance.js     实例装配与显式锁定
  contract.js     查询契约、哈希与边界声明
  truth.js        独立真值表
scripts/generate-sample.js   确定性样本生成器（固定种子）
static/                      原生 HTML/CSS/JS 页面
tests/                       node:test 测试
```

## 明确的边界

- 只覆盖“单地区人数”这一种计数查询，不适用于任意查询/数据/统计量。
- 不处理锁定后的数据修改、合并或版本迁移；锁定数据是唯一计数对象。
- 只用基本组合，不做自适应预算分配或高级组合。
- 非负截断只影响展示分布，不提供隐私保护，且引入系统性偏差。
- 预算与锁定以 SQLite 文件为信任锚；能删除/改写文件的人不在威胁模型内。
- 管理员令牌只用于区分“设置预算/锁定”与“提交查询”，不是完整认证方案。
- 真值页是教学/验收用的独立入口，真实部署不应向查询用户暴露真值。
